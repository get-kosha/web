# Kosha

Personal finance tracker: a TanStack Start app on one Cloudflare Worker with a D1 (SQLite) database. `README.md` is the user-facing guide to features and setup. This file covers how the code fits together and the rules it depends on.

## Where things live

- `src/lib/core.ts`: pure helpers shared by client and server, covering money, dates, categorising and subscription schedules. Put new logic here when it has no I/O, so it can be tested.
- `src/lib/api.ts`: every server function (`createServerFn` with a zod validator). Pages call these, never the database. They only validate and pass the signed-in user's id on.
- `src/server/ai.server.ts`: AI provider keys (encrypted), and `chat()`, which talks to Anthropic's Messages API, OpenAI's Responses API, and the Chat Completions format everyone else speaks. It also writes the request log. `src/server/ai-tasks.server.ts` holds the AI features: their prompts, what they send, the recap facts and Ask Kosha's look-up tools. `aiFeatures()` in `core.ts` decides which features are live, and `getMeta()` returns that as `meta.ai`; a feature that is off renders nothing.
- `src/lib/statement.ts`: pure statement helpers: CSV and OFX parsing, column guessing, bank text to payees, matching statement lines to entries, and the difference hints. `src/server/statements.server.ts` reads and writes for them: the Reconcile page's data, finishing and undoing a reconciliation, adding statement lines, and recurring suggestions (`findRecurring` in `core.ts`). The page is `src/routes/_app/reconcile.tsx`. `src/routes/_app/import.tsx` imports many statements at once into new or existing accounts (statements → accounts → payees → saved); the Get started banner in `src/components/get-started.tsx` leads there while an account has no transactions, and `finishImport` sets each account's opening balance and reconciles it.
- `src/server/loans.server.ts`: personal loan agreements and principal payments. `src/lib/loans.ts` owns their schemas and summaries; `/loans` is the Loans view under Accounts. Payments link bank transactions without duplicating them. Principal is neutral; agreement balances add receivables and liabilities to net worth. Interest terms and expected instalments can be added separately from actual payments.
- `src/server/finance.server.ts`: what the app does with money data. Each function takes the user's id first, so the UI's server functions and the public API run the same code. Writes take lists and run as one batch.
- `src/server/db.server.ts`: database helpers, exchange rates, subscription settling, transfer legs and `HttpError`. `src/server/auth.server.ts`: Better Auth setup, `userId()`, the OAuth provider for MCP, and profile pictures. Pictures live in the optional R2 binding `AVATARS`; when a deployment has none, `getMeta().avatars` is false and the upload hides, so never assume the binding exists.
- `src/components/auth.tsx`: the sign-in pages' frame (`AuthShell`, the brand panel) and controls. `/login`, `/forgot-password`, `/reset-password`, `/auth/error`, `/consent` and `/app/oauth/callback` sit outside `_app`; the reset pages, auth error page and callback are listed in `SIGNED_OUT_PAGES` in `start.ts`, and a signed-out browser can't call server functions, so their loaders run on the server. `/auth/error` is Better Auth's global OAuth error fallback; individual Google flows keep their own error callbacks. Brand colours and Bricolage appear only in the panel and the logo.
- `src/server/email.server.ts`: `sendEmail` over SMTP (worker-mailer). Templates are react-email components in `src/emails/` (`npm run email` previews them). Without `SMTP_HOST`, dev prints each email to the terminal.
- `src/server/attachments.server.ts`: receipts and payslips on transactions, kept in the optional R2 binding `ATTACHMENTS` under `<user_id>/<id>` and served by `src/routes/api/attachments/$id.ts`. `getMeta().attachments` is false without the binding, and `src/components/attachments.tsx` then renders nothing. Triggers in `0008_attachments.sql` delete a transaction's attachment rows and queue the R2 keys in `attachment_trash`, which `getMeta` purges after replying, so no delete path needs to handle files itself. The exception is a deleted subscription payment, which becomes a skipped row, so `deleteTransactions` removes its files explicitly.
- `src/lib/api-contract.ts`: the public API. Each entry in `OPERATIONS` is one REST endpoint under `/api/v1` and one MCP tool at `/mcp`, with its schemas, description and examples. It also builds the OpenAPI document. `src/server/api.server.ts` holds a handler per operation, API keys, token checks, the REST router and the MCP server. To add an operation, add an entry and its handler; `npm test` checks the examples against the schemas. Cursor passes only the first 40 tools to its agent, so add everyday operations before `undo_reconciliation`, and AI or rarely needed ones at the end; the test checks the order. An operation that uses the AI model sets `ai`, and fails with `ai_unavailable` (409, from `aiBlocker` in `core.ts`) when AI isn't set up, or `ai_provider_error` (502) when the provider fails.
- `src/server/app-api.server.ts`: `/api/app/*`, the endpoints only Kosha's phone apps call (meta, preferences, profile, attachments, statement import, AI providers and log, API keys, export, Delete & reset). They take only access tokens issued to `APP_CLIENTS` (`auth.server.ts`), the public OAuth clients `migrations/0009_app_clients.sql` registers. The apps redirect to `APP_CALLBACK` (`/app/oauth/callback`), which they claim through `/.well-known/assetlinks.json` and `apple-app-site-association` (`ANDROID_CERT_SHA256`, `APPLE_TEAM_ID`); only that redirect skips consent, and the `app.getkosha:` scheme always shows it. `scripts/setup-app-clients.ts` sets their redirects and resource links after migrations in `npm run db:migrate` and before deployment in `npm run deploy`, using the configured origin. Auth requests never provision clients or share setup I/O. Each app access token carries `grant_id`, its sign-in, and `fromAccessToken` accepts it only while that sign-in has a live refresh token. They mirror the server functions in `api.ts`, so put shared logic in a `src/server/` module both call. They are not MCP tools and not in the OpenAPI document. The apps sign out by revoking their refresh token at `/api/auth/oauth2/revoke`.
- `src/routes/_app/*`: signed-in pages. `src/routes/_app.tsx` owns the `currency` search param, which follows you between pages, and the `month` param that only Overview and Accounts use (it isn't carried to other pages). Activity has its own `period` (`parsePeriod` in `core.ts`): unset, a search, tag or event covers every date and anything else the current month, which `listTransactions` mirrors. It loads `getMeta()` once for every page. `/login` sits outside `_app`, so it loads no account data. So do `/privacy`, `/terms` and `/delete-account` (framed by `src/components/legal.tsx`), which state what the hosted service stores, sends and deletes; update them when that changes, such as a new table of user data or a new outside service. Google Play's store listing links to `/delete-account`, so it stays public.
- `messages/<locale>/<area>.json`: every message people read, in English (`en`, the source) and every language listed in `translations.md`. Paraglide JS compiles them into typed functions in `src/paraglide/` (generated and git-ignored; `npm run i18n`, and the Vite plugin in dev and build). `translations.md` explains the format, lists the languages and holds the glossary.
- `src/components/ui/*`: shadcn/ui components on Base UI. App components sit beside them in `src/components/`.
- `src/components/settings/*`: the Settings area. `registry.tsx` lists every section and its searchable rows; the rail, phone list and search read it. Each setting is a `SettingRow` that saves itself (`usePref` / `useSave`), and every preference key with its values and default lives in `PREFS` in `core.ts`.
- `migrations/`: numbered D1 migrations. To change the schema, add the next numbered file. Production has applied `0001_init.sql`, so never edit a migration that is already in the repo. `npm run deploy` applies pending migrations before it deploys, so keep each migration compatible with the code currently running.
- `src/sw.js`: the service worker. A plugin in `vite.config.ts` builds it into `/sw.js` with the build's asset list and a version hash, so each deploy installs a new worker. It precaches built assets and keeps pages and GET server-function replies (network first) for offline use; POSTs, auth, `/api` and `/mcp` bypass it. `src/components/pwa-prompts.tsx` registers it (production builds only) and shows the offline, update and install cards. `src/lib/offline.ts` queues new transactions added offline and sends them when the connection returns. Sign out through `signOut()` in `auth-client.ts`, which also clears the saved pages.
- `scripts/`: Node scripts run directly as TypeScript. They cover the Cashew import, the demo seed, and `ai-stub.ts`, a fake OpenAI-compatible provider for trying AI features in `npm run dev` without a key (dev allows `localhost` endpoints; production doesn't).
- `src/server.ts`: the Worker's entry (wrangler `main`). A GET with no session cookie and no query string to `/`, `/privacy`, `/terms` or `/delete-account` is served from the Cache API for 5 minutes, keyed by deployed version and locale, before the app loads. Those pages must render the same for every signed-out visitor in a language, so nothing on them may depend on other cookies, headers or the time. Better Auth loads lazily too: `start.ts` and `guestVisit` skip it without the cookie (`hasSessionCookie`), and server routes import their modules inside the handler, so a page request never evaluates the API, MCP or the OAuth provider.
- `src/routeTree.gen.ts` and `worker-configuration.d.ts` are generated. Regenerate them with `npm run generate-routes` and `npm run cf-typegen`.

## Data rules

These invariants hold across the codebase. Breaking one gives wrong totals without any error.

- **Every query is scoped by `user_id`, including joins.** Each data table's primary key is `(user_id, id)`, so ids are only unique per user. A join on `id` alone mixes users' data. Only the `rates` table is shared.
- **Amounts are integer cents, and the sign is the direction** (negative means money out). Parse user input with `parseAmount` and format with `fmt`.
- **Timestamps are unix seconds. Days and months are strings in the user's time zone** (`YYYY-MM-DD`, `YYYY-MM`). Convert with `dayOf`, `unixOf` and `monthRange`, not with `Date` arithmetic.
- **Category `0` (corrections) and `transfer` are neutral.** Loan principal (`loan_principal`) is neutral too. Income and spending totals leave them out, using `isNeutral` or `NEUTRAL_SQL`. `transfer_fee` is a system category too, but it counts as spending. See `isSystemCategory`.
- **A transfer is two rows linked by `transfer_id`**, one out and one in, each in its own account's currency. Keep both rows in sync on every create, edit and delete.
- **A refund is its own money-in row with `refund_of`** set to the spending entry it undoes, in whichever account the money came back to, with that entry's category. Totals count it as spending undone, never income: split income and spending with `INCOME_SQL`/`SPENDING_SQL`, not the amount's sign alone. Deleting the entry deletes its refunds, and editing its category moves them too.
- **Tags are a JSON array in `transactions.tags`** (lowercase, no `#`). Clean input with `parseTags`/`cleanTag`, read with `tagList`, and filter in SQL with `json_each`. A tag filter, like an event filter, covers every date unless a day range is given.
- **Events are optional date ranges.** `saveTransaction` gives a new entry the event its day falls in (`eventFor`) when no `eventId` is sent; `undefined` keeps an edit's event and `null` clears it. `event_id` has no foreign key, so `deleteEvent` clears it.
- **Subscriptions are schedules, not rows.** Upcoming payments are computed from the schedule. A transaction row is written only when a payment is paid, edited or skipped. Due payments are settled when the app loads (`ensureSettled`), and there is no cron job.
- **Exchange rates are stored as units per 1 USD** and refresh at most once a day from the fawazahmed0 currency API. Convert with `convert(cents, from, to, rates)`.
- **A server function that changes data is a POST, and one that only reads is a GET.** The demo account (`DEMO` in `core.ts`) is read-only, and `start.ts` enforces that by refusing every POST server function for it. A write behind a GET would slip past. Better Auth's own endpoints are gated in `routes/api/auth/$.ts`, and API tokens for the demo account are read-only.
- **A reconciled entry has `reconciled_id` set.** Changing its amount, account or day clears it, and the UI warns first. A reconciliation stores the balance as Kosha keeps it (available credit for a card) with the card's limit then. Only an account's latest reconciliation can be undone. Imported entries keep the bank's id in `bank_ref`, so importing a file again matches them instead of adding them twice.
- **AI requests send only what Settings › AI › What AI can see allows.** Use `redactForAi` and `payeeCode` for anything about transactions, and `unmask` on replies, so hidden payees and account refs read as real names. AI calls are POST server functions, since each is logged and spends the user's tokens.
- **The public API speaks its own shapes.** It says account (not wallet) and payee (not name), and uses camelCase. Handlers in `api.server.ts` translate. Bulk writes are all-or-nothing and report every invalid field as `transactions.3.accountId`. Auth, AI keys, export and Delete & reset stay out of the public API on purpose; the phone apps reach them through `/api/app`. `/api/v1` takes API keys and OAuth access tokens for `/api/v1` or `/mcp`.
- **Net worth depends on account type** (bank, credit card, investment). Use `accountWorth` and `netWorth` rather than summing balances.

## UI conventions

- `DESIGN.md` describes the design system as built: tokens, type, layout, components, motion and the landing and sign-in surfaces. Read it before building a new screen.
- Icons come from Phosphor (`@phosphor-icons/react`). Category icons map the stored emoji to a Phosphor icon in `category-icon.tsx`.
- Colours come from the theme tokens in `src/styles.css`. Light and dark mode must both work. Dark mode is the `.dark` class on `<html>`.
- Confirmations (delete, end subscription) use the `Dialog` component.
- Use real `<button>` and `<a>` elements. Give icon-only buttons an `aria-label`, and give segmented toggles `aria-pressed`. Touch targets on phones are at least 44px.
- Toasts use `sonner`. Charts use Recharts through `components/ui/chart.tsx`.
- Every string people read comes from `m.*()` (`import { m } from "@/paraglide/messages"`; files in `src/lib/` that `npm test` runs import `../paraglide/messages.js`). Add the key to the area's file in every `messages/<locale>/` folder, using `translations.md`'s glossary, and `npm test` checks they match. Call `m.*()` only at render or call time, never at module top level. Use whole sentences with `{variables}`, plural variants instead of `n === 1 ?`, and `ParaglideMessage` markup for links inside a sentence. Format numbers and dates with `fmt` and `intlLocale()`.
- The language comes from the `kosha-locale` cookie, then the browser's languages. A middleware in `start.ts` sets it per request, so server errors, emails and AI replies follow it, and the public API and MCP stay English. The exception is `/api/v1` called with a token of Kosha's own apps: `handleRest` runs it in the request's `Accept-Language`, so errors a person can cause should use `m.*()`. The landing page, sign-in pages and Settings › General switch it; a signed-in account also stores it in the `language` preference.

## Checking your work

Before you finish, run all five. Each one must pass.

- `npm test` runs `src/lib/core.test.ts`, a plain `node:assert` self-check, including `loans.test.ts` against the real migrations in an in-memory SQLite database. When you change logic in `core.ts` or `quick-add.ts`, add asserts there.
- `npm run typecheck` type-checks with tsrs, the Rust port of the TypeScript 7 checker. There is no `typescript` package in this repo.
- `npm run lint` runs oxlint. Fix any new error. The React warnings (`purity`, `set-state-in-effect`, `static-components`, `immutability`, `exhaustive-deps`) are known, so leave them unless you are changing that code.
- `npm run format` formats with oxfmt, which also sorts Tailwind classes. `npm run check` verifies the formatting.
- `npm run knip` must report nothing. If it flags a dependency, file or export you just stopped using, delete it. Code in `src/components/ui/` comes from shadcn, so knip ignores its unused exports.
- To check the app in a browser, sign in as `demo@kosha.local` with the password `kosha-demo-2026`. Run `npm run db:demo` to reset it. The demo account is read-only unless `.dev.vars` has `DEMO_WRITABLE=1`. Never use or screenshot real account data.

## Commits

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org): `type(scope): subject`, with a header of 100 characters or fewer. The scope is optional, and `!` after the type or scope marks a breaking change. The types are `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore` and `revert`.

Git hooks in `.githooks/` enforce this. `npm install` turns them on through the `prepare` script. `pre-commit` runs `npm run check` and `npm run lint`, and `commit-msg` checks the header. If a hook fails, fix the cause and commit again.

## Code style

- Write comments that explain why. Keep them short and put them above the code they describe.
- When you take a deliberate shortcut with a known limit, mark it with a `ponytail:` comment that names the limit, e.g. `// ponytail: unknown currency passes through unconverted`.
